# Visual matching evaluation

Generated by:

```sh
swift run -c release photosweep-dev make-fixtures
swift run -c release photosweep-dev evaluate --thresholds 4 6 8 10 12 14 16 18
```

Fixture set: 32 CC0 photos from Wikimedia Commons (see [Fixtures/CREDITS.md](../Fixtures/CREDITS.md)). 20 of them get ten edited variants each (resized, recompressed, PNG, HEIC, brighter, warmer, contrast/saturation, EXIF-rotated, rotated 90°, center-cropped 80%). The other 12 are *different photos of the same subject*: burst-style shots of the same car, locomotive, road, air display and roadside lift, with no edited variants. These are the hardest negatives: a user may or may not consider them duplicates, but they are not the same image. The set also includes look-alike scenes such as two different country roads.

Evaluated 232 decodable images: 32 originals, of which 20 have edited variants.
Excluded 22 files: 2 damaged file (exact match only), 20 byte-identical copy (exact match).

A *pair* is two images placed in the same visual group. A pair is **correct** when both images derive
from the same source photo. **Precision** = correct pairs ÷ proposed pairs. **Recall** = correct pairs ÷
all same-source pairs (including hard cases such as rotation and cropping).

## Reading the results

- **Default threshold 10.** Every proposed pair from 4 through 12 was correct on this set. Errors start at 14 (one unrelated pair) and climb quickly from 18. Threshold 10 sits in the middle of the clean range: every encoding, resize, white-balance and orientation-metadata variant is recovered, plus 19 of 20 contrast edits.
- **What dHash misses.** True 90° rotations (distance 18–39) and 80% crops (distance 10–28) are almost never recovered at safe thresholds. Raising the threshold recovers more crops but adds false matches faster. These cases need a different algorithm (multiple rotations, or features that survive crops) and are out of scope for v1.
- **Same subject, different photo.** Burst-style shots of the same subject were 16 or more bits apart and were never grouped at the default threshold. dHash compares global structure, so even small camera movement changes many bits.
- **Recall is pair-based** and includes variant–variant pairs (for example, "rotated" vs "cropped" of the same source). That is why it stays well below 100% even at thresholds where every simple edit is recovered.
- **Limitations of this evaluation.** It uses 20 source families, the edits are synthetic, and many photos are city and road scenes. It shows the algorithm's behavior; it does not estimate accuracy on any particular library.
